Классы и объекты

Навык: отличить чертёж (класс) от экземпляра (объект) и видеть, из чего класс состоит.

Класс = бланк, объект = заполненный бланк

Из твоего мира: класс — это шаблон тест-кейса в TMS. Сам по себе он ничего не делает — это форма с полями. Объект — конкретный тест, созданный по шаблону: заполнены поля, у него своё состояние.

class TestUser { ... }              // класс — шаблон

var u1 = new TestUser("admin", "x"); // объект 1 — экземпляр по шаблону
var u2 = new TestUser("guest", "y"); // объект 2 — другой экземпляр, свои данные

new — команда «создай объект по этому чертежу». У u1 и u2 одинаковое устройство (один класс), но разные данные (свои поля).

Из чего состоит класс

Открой LoginPage.cs — вот его скелет без кода:

public class LoginPage
{
    поля        private readonly FakeDriver _driver;   // внутренняя память объекта
    константы   private const string LoginField = "#login";

    конструктор public LoginPage(FakeDriver driver)    // отрабатывает при new

    методы      public LoginPage Open() { ... }        // что объект умеет делать
                  public bool IsOnDashboard() => ...
}

Три разновидности «переменных в классе» — теперь различаем их точно:

Как узнатьЗачемПример
полестрока внутри класса, но вне методов, без getвнутренняя память объекта: методы пишут и читают её между собой_driver
свойствоу него есть { get; } или { get; set; }данные объекта, доступные снаружи: user.LoginCurrentUrl
локальная переменнаяобъявлена внутри { } методавременная — умирает, когда метод закончилсяbool ok в Click()

Конструктор — «инструкция по сборке»

public LoginPage(FakeDriver driver)   // имя = имя класса, возвращаемого типа нет
{
    _driver = driver;                     // положили присланный драйвер в поле
}

Признак конструктора: имя совпадает с именем класса и у него нет типа возврата. Запускается один раз — в момент new. Всё, что он получил в параметрах, раскладывает по полям — поэтому методы ниже могут драйвером пользоваться.

static — «принадлежит классу, а не объекту»

var page = new LoginPage(driver);
page.Open();                    // обычный метод — у объекта

TestUser.CreateDefault();       // static — у самого класса, new не нужен
Console.WriteLine("x");         // Console — static-класс, объектов не создаём

Видишь вызов без new и с большой буквы — это static.

Цепочки вызовов

page.Open().EnterLogin("admin").Submit();
// читаем слева направо: каждый метод вернул page (return this),
// и у него же вызван следующий метод

Проверь себя

Чем объект отличается от класса?

  • класс — это экземпляр, объект — это шаблон класса
  • класс — шаблон, объект — экземпляр со своими данными
  • ничем не отличаются — это два имени одного

Как распознать конструктор в коде класса?

  • имя совпадает с именем класса, нет типа возврата
  • метод со словом static в объявлении
  • метод с именем Constructor или Create

private readonly FakeDriver _driver; внутри класса, но вне методов — это…

  • свойство класса
  • поле класса
  • локальная переменная

TestUser.CreateDefault() вызван без new и без объекта. Значит метод…

  • приватный
  • статический (static)
  • асинхронный (async)

Твой выигрыш

Теперь файл LoginPage.cs читается как устройство: поля — память, конструктор — сборка, методы — кнопки управления. Эта же структура повторяется в любом Page Object реального проекта.
