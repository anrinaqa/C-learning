Как читать упавший тест

Stack trace — это не хаос, а карта. Читается сверху вниз.

Анатомия падения

Failed Login_VariousCredentials(login: "admin", password: "x")
  Assert.Equal() Failure          // КТО упал: проверка Assert.Equal
  Expected: True                  // что ОЖИДАЛИ
  Actual:   False                 // что ПОЛУЧИЛИ
     at TestExample.Tests.LoginTests.Login_VariousCredentials(...)
     in Tests\LoginTests.cs:line 75   // ГДЕ: файл + строка — смотри сюда!

Алгоритм за 30 секунд

  1. Какой тест? — имя в первой строке + параметры из InlineData
  2. Тип ошибки? — Assert.*Exception (тест отработал, но проверка не прошла) или NullReference/Timeout (код упал сам)
  3. Expected vs Actual — что сравнивалось и на чём разошлось
  4. Первая строка СВОЕГО кода — в stack trace ищи первую строку НЕ из System.* и не из NuGet-пакетов. Там файл:line

Типы ошибок в автотестах

ОшибкаЧто случилосьКуда смотреть
Assert.Equal/True Failureкод отработал, результат не тотожидаемое значение, тестовые данные
NullReferenceExceptionобратились к nullчто могло не вернуться/не создаться
NoSuchElementExceptionSelenium не нашёл элементселектор! изменилась вёрстка?
TimeoutExceptionне дождались элемент/страницумало времени ожидания или реально нет элемента
StaleElementReferenceэлемент «протух» — страница обновиласьнужно найти элемент заново
