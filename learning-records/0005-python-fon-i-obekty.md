# Python-фон и модель объектов

Ученица раскрыла: есть поверхностное знакомство с Python («как в python» — атрибуты экземпляра). Раньше заявлялся нулевой техбэкграунд — уточняем: базовое понимание классов/объектов из Python есть, это актив, а не ноль.

**Misconception, поправленная**: путала поле/свойство (в Python атрибут ≈ C#-поле) и считала, что конструктор создаёт один объект с двумя «свойствами» — на деле `new` на каждый объект, поля хранят ссылки на отдельные объекты. Принято с опорой на Python-аналогию (@property ≈ C#-свойство).

**Implications**: можно смело опираться на Python-аналогии (self, атрибуты, duck-typing vs static types). Также отмечено: задала ревьюерский вопрос про избыточность `return this` в последнем методе цепочки — мышление «зачем этот код» уже работает.
